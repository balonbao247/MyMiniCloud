Kinh Nghiệm Thực Chiến Làm Chủ Docker & Microservices

DV DevOps Lead EngineerVận hành & tự động hóa container 📅 05/11/2026⏱ 7 phút đọc

Nội dung

Khi xây dựng MyMiniCloud, việc điều phối 12 container gồm Nginx Proxy, Flask, MariaDB, Keycloak, MinIO, BIND9 và cụm Prometheus/Grafana đòi hỏi hiểu sâu về Docker Compose và Networking.

⚡ Tuyên ngôn DevOps Container hóa đóng gói toàn bộ dependencies, đảm bảo môi trường đồng nhất tuyệt đối từ máy Local đến máy chủ Cloud.

1. Ba nguyên tắc vàng khi viết Dockerfile

  • ✓
    Ưu tiên Alpine base image: giảm dung lượng từ ~1GB xuống ~50MB (python:3.11-alpine, nginx:stable-alpine).
  • ✓
    Tối ưu cache layer: copy requirements.txt và cài thư viện trước khi copy mã nguồn để khỏi cài lại mỗi lần sửa code.
  • ✓
    Dọn cache khi build: luôn dùng --no-cache-dir với pip để image gọn nhẹ nhất.
application-backend-server / Dockerfile
# Alpine siêu nhẹ để tối ưu tài nguyên FROM python:3.11-alpine WORKDIR /app # Cache lớp thư viện Python COPY requirements.txt . RUN pip install --no-cache-dir -r requirements.txt # Copy ứng dụng Flask và dữ liệu sinh viên COPY app.py students.json ./ EXPOSE 8081 CMD ["python", "app.py"]

2. Sức mạnh của user-defined network

Bridge mặc định không hỗ trợ phân giải tên container bằng DNS nội bộ. Khi khai báo mạng riêng:

docker-compose.yml
networks: cloud-net: name: cloud-net driver: bridge

API Gateway có thể chuyển tiếp tới http://application-backend-server:8081/ mà không cần quan tâm IP động của container.

Một kiến trúc mạng Docker sạch sẽ là nền tảng để triển khai rolling update và cân bằng tải hiệu quả.

3. Bài học khi deploy lên AWS EC2

Khi đưa 12 container lên EC2 t3.micro (chỉ 1GB RAM), hệ thống dễ crash do Keycloak (Java) ngốn bộ nhớ. Giải pháp bắt buộc là tạo 2GB Swap — kinh nghiệm xương máu giúp hệ thống chạy ổn định.
